# Обновления Marketplace Transfer

Клиент проверяет стабильные публичные GitHub Releases через HTTPS. В приложение встроен открытый ключ Ed25519. Перед установкой проверяются подпись манифеста, версия, платформа, совместимость схемы SQLite, размер и SHA-256 установщика. Имя файла и адрес привязаны к выбранному репозиторию и тегу версии. Разрешены только HTTPS-перенаправления на известные хосты файлов GitHub.

Сейчас реального репозитория нет: онлайн-проверка и установка настоящего опубликованного релиза **не подтверждены**. В программе это отображается как ненастроенный источник, а не как успешная проверка. Локальные тесты используют явно обозначенные тестовые репозитории и HTTP MockTransport.

## Однократная настройка

1. Создайте настоящий публичный репозиторий GitHub для релизов. Не загружайте в него пользовательскую базу, фотографии, папки outputs/work и приватный ключ.
2. В Marketplace Transfer откройте «Настройки», укажите HTTPS-адрес репозитория и нажмите «Сохранить источник обновлений». Программа сохранит источник; закреплённый ключ доверия останется прежним.
3. Перед сборкой публикации настройте тот же репозиторий в исходниках: `python scripts/configure_updates.py https://github.com/OWNER/REPOSITORY` (замените OWNER/REPOSITORY настоящими значениями).

## Выпуск версии на этом Windows-компьютере

1. Измените версию в `marketplace_transfer/__init__.py` и `pyproject.toml`; дополните `RELEASE_NOTES.md`.
2. Выполните `python -m pytest -q` и `node --test tests/extension.test.cjs`.
3. Создайте и отправьте тег `v<версия>` в ваш репозиторий. Скрипт публикации использует `--verify-tag` и не создаёт тег неявно.
4. Установите официальный GitHub CLI и один раз выполните `gh auth login` самостоятельно. Авторизация GitHub не передаётся в Marketplace Transfer.
5. Выполните `powershell -ExecutionPolicy Bypass -File scripts/publish_release.ps1 -Repository OWNER/REPOSITORY`.

Скрипт соберёт Windows EXE, отдельный updater и установщик, подпишет `MarketplaceTransfer-update.json`, проверит подпись/размер/SHA-256 локально и загрузит два файла в релиз: `MarketplaceTransfer_Setup.exe` и `MarketplaceTransfer-update.json`. Без реального репозитория подпись установщика можно проверить локально, но это не онлайн-тест.

Приватный ключ хранится **вне проекта**: `%LOCALAPPDATA%\MarketplaceTransferSigning\signing-key.dpapi`. Он защищён Windows DPAPI текущего пользователя и ACL. В исходники и установщик попадает только открытый ключ `updating/update_config.json`. Не удаляйте приватный ключ и не копируйте его в репозиторий. DPAPI-привязку к пользователю/компьютеру нужно учитывать при резервном копировании системы: перенос одного файла на другой ПК не позволяет его расшифровать. Новую пару нельзя молча генерировать вместо потерянной — старые клиенты доверяют прежнему ключу.

Подпись Ed25519 относится к подписанным метаданным, связывающим точную версию с SHA-256 и размером EXE. Это не сертификат Authenticode Windows; такой сертификат не предоставлялся.

## Установка и откат

При тестировании копии установленной программы нельзя копировать и запускать старые `unins*.exe`/`unins*.dat`: журнал Inno содержит абсолютные пути исходной установки. Изолированные проверки используют отдельный AppId и uninstaller, полученный из его собственной записи реестра; исходные unins-файлы в тестовую копию не переносятся.

Пользователь выбирает «Скачать и установить» или «Позже». Загрузка идёт в отдельной фоновой задаче. Если перенос или другая операция активна, установка ждёт её завершения; пауза очереди не обходится. Программа закрывается, отдельный процесс проверяет подпись повторно, сохраняет программу и SQLite, запускает установщик и проверяет новую версию, целостность истории и товарных связей.

При ошибке установщика или проверки запуска восстанавливаются прежние программные файлы и база, затем запускается старая версия. Неудачные файлы сохраняются в папке задания для диагностики; фотографии и пользовательские папки не удаляются. Межпроцессная блокировка запрещает параллельные обновления. Резервные копии перед миграцией находятся в папке данных `backups`.

Если компьютер выключился во время замены файлов, используйте «Пуск → Восстановление Marketplace Transfer». Если сам каталог программы повреждён, запустите сохранённый `%LOCALAPPDATA%\MarketplaceTransferNew\updates\jobs\<идентификатор>\MarketplaceTransferUpdater.exe --recover-latest`. Перед восстановлением закройте приложение. Состояние и журнал находятся в `updates/last-result.json` и папке соответствующего задания. Принудительное выключение питания и настоящая перезагрузка ПК при разработке не проводились.

При незавершённой установке обычный запуск программы блокирует новые переносы до восстановления. Это предотвращает откат базы поверх новых результатов, появившихся после прерванного обновления.

## Ручная проверка подписанного файла без установки

`MarketplaceTransferUpdater.exe --verify-installer MarketplaceTransfer_Setup.exe --manifest MarketplaceTransfer-update.json --verification-report verification.json`

Отчёт подтверждает только подпись и точный файл. Проверки реального GitHub, совместимости и установки являются отдельными этапами.
